# DeployFlow

**把可视化部署流程、SSH 终端和 SFTP 文件管理放在一起的 Windows 桌面工具。**

[English](README.md) · [简体中文](README_CN.md) · [繁體中文](README_TW.md) · [日本語](README_JA.md) · [한국어](README_KO.md) · [Español](README_ES.md)

## 为什么做 DeployFlow

对于个人开发者和小团队，只发布几个项目，也可能需要为完整的自动化部署平台投入额外的搭建、配置和维护成本。完全依靠终端操作，又经常要反复输入命令、复制路径、切换传输窗口，发布步骤一多就容易遗漏。

DeployFlow 将已有的构建工具和脚本组织成本地桌面流程：按顺序完成打包、连接、上传、执行脚本和健康检查，再直接通过内置终端、文件窗查看结果。

它适合**个人开发者、小型研发团队，以及经常部署或排查 Linux 服务器的开发人员**，用于日常服务发布、前端资源上传和服务器操作。当前不提供集中调度、多人审批或分布式执行。

![可视化部署流程和右侧步骤参数](docs/screenshots/workflow.png)

*示例：Maven 打包 → 连接服务器 → 上传产物 → 部署脚本 → 健康检查。截图使用英文界面；用户命名、脚本内容和命令输出保留原文。*

## 把发布清单变成可复用流程

通过添加有顺序的步骤创建任务。单击节点查看参数，双击编辑，拖动调整顺序；选中节点后添加步骤，会插入到它后面，未选中时追加到末尾。流程窗和参数窗可以分别显示，也可以同时打开。

| 步骤 | 用途 |
| --- | --- |
| 连接服务器 | 读取已保存的配置，创建供后续步骤使用的命名 SSH 连接。 |
| 合并分支／推送分支 | 按配置执行 Git 拉取、合并、提交和推送操作。 |
| Maven 打包 | 构建项目，识别 JAR 产物，供后续上传引用。 |
| 本地命令／本地脚本 | 在指定工作目录执行 Windows 命令或脚本，支持超时和脚本参数。 |
| 上传文件 | 上传产物、文件或文件夹，可创建目标目录并备份已有文件。 |
| 远程命令／远程脚本 | 通过指定连接执行命令或已保存的 Shell 脚本。 |
| 等待 | 等待设定秒数后继续。 |
| 健康检查 | 周期执行检查命令，达到连续成功次数后通过，超时则失败。 |

右上角的**执行**按钮在未选中节点时运行整个任务，选中节点时按原顺序执行选中步骤。节点右键还支持**单独执行此步骤**和**从此位置开始执行**。执行时可查看输出、进度、超时和失败信息，也可以停止任务。

局部执行不会自动补跑前置步骤。后续操作需要连接或打包产物时，应把创建这些依赖的步骤一起选中执行。

## 终端里的路径，可以直接操作

看到命令输出中的目录或文件后，可以直接操作，减少复制路径、切换窗口和重新输入命令。

- **Ctrl＋悬浮**：按住 Ctrl，把鼠标移到可识别的路径上，显示下划线。
- **Ctrl＋左键**：目录会联动跳转终端和下方文件窗；文件会跳转到它所在的目录。
- **路径右键**：既可以选中文本后右键，也可以不选中，直接在路径上右键。识别后显示对应操作。
- **继续处理文件**：打开文本编辑器、执行脚本或填写后续参数、修改权限，以及跟踪日志、查看最后 N 行、查询关键字。

路径需要能在当前服务器上解析，相对文件名需要对应的目录信息；各 SSH 页签分别维护自己的目录上下文。

![终端与下方文件目录联动](docs/screenshots/remote-files.png)

## 保存服务器信息和常用位置

通过表单配置地址、端口、账号和认证信息。密码与私钥可以同时保留，由选中的认证方式决定实际使用哪一种。

每台服务器可以保存多条访问路径和可选命令。可以设置默认路径及是否执行命令，也可以点击**直接连接**、双击路径行或使用右键菜单，直接连接到某个位置。

![服务器配置、认证方式和默认访问位置](docs/screenshots/server-config.png)

系统设置提供密码保护和**隐藏IP**。例如 `192.168.10.25` 可在支持的地址显示位置变成 `192.**.**.25`，连接仍使用真实值；关闭隐藏后可修改地址。该选项不会清除日志或任意远程输出中的真实 IP。

## 完整的 SSH 操作窗口

通过页签旁的 **+** 打开其他已保存的服务器。既可以使用编辑页面下方的终端面板，也可以切换到**终端模式**，获得更大的操作区域。

终端使用 Qt WebEngine 和 xterm.js，支持 Shell 补全、命令历史、复制粘贴、中断和重连。左侧实时展示 Linux 系统与内核、运行时间、负载、CPU、内存、交换区、磁盘，以及运行程序的端口和资源占用。可查看进程命令，通过右键停止或尝试重启进程。

![SSH 终端及 Linux 服务器实时信息](docs/screenshots/ssh-monitor.png)

进程重启标记为**不建议**：从运行进程读取的信息可能无法还原启动脚本、管道和日志重定向。需要保留这些行为时，应使用原启动脚本或服务管理器。

## 两种文件管理布局

**双栏 SFTP 窗口**：左侧选择本地磁盘和目录，右侧浏览服务器。可以上传选中项，也可以从本地列表或 Windows 资源管理器拖拽文件、文件夹到远程列表。

![本地与服务器双栏 SFTP 文件传输](docs/screenshots/sftp-transfer.png)

**内嵌远程文件窗**：位于终端下方，提供目录树、路径导航、访问历史和文件详情。旁边的 **Logs／日志** 页签可以查看本次连接日志。

两种界面都支持上传下载、远程复制／剪切／粘贴、重命名、删除、新建文件和文件夹、修改权限及独立文本编辑器。远程复制粘贴在同一服务器连接标识内进行。上传／下载面板显示多个传输任务，删除进行中的任务即可取消，完成后可打开下载位置；也可以将远程文件拖到 Windows 资源管理器中的文件夹，下载到该位置。

## 复用脚本，回看修改和执行记录

在**脚本**页面保存本地构建、远程部署脚本，再从任务中引用。本地支持 `.bat`、`.cmd`、`.ps1`、`.sh`、`.bash`；远程流程脚本使用 `.sh` 或 `.bash`。

![内置脚本编辑页面](docs/screenshots/script-editor.png)

任务、配置和脚本支持自动暂存与历史版本，使用**保存／Ctrl＋S**写入正式文件。历史支持预览、恢复、多选和删除。在软件内重命名配置或脚本时，会同步更新当前 JSON 流程、草稿及流程历史中的引用。

执行与 SSH 日志按日期存放，文件名包含创建时间，日志条目带时间戳。即使清空执行输出，仍可在**日志**页面回看或删除已保存的记录。

![持久保存的任务和连接日志](docs/screenshots/logs.png)

## 快速开始

### 环境与启动

- Windows 64 位；当前开发环境使用 Python 3.12。
- 远程操作需要 SSH／SFTP 服务，监控与远程脚本主要面向 Linux 服务器。
- 按步骤准备工具：Git；JDK 与 Maven 或项目自带 Maven Wrapper；前端脚本使用的 Node.js／npm；执行本地 Shell 脚本所需的 Bash。

在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\start.bat
```

直接启动或在 IDE 运行时，解释器选择 `.venv\Scripts\python.exe`，入口选择 `app\qt_main.pyw`：

```powershell
.\.venv\Scripts\python.exe app\qt_main.pyw
```

已有免安装版本时，保留完整程序目录，运行 `DeployFlow.exe`。

### 第一个任务

1. 在**配置**中新建并保存服务器。
2. 在**脚本**中添加需要的构建或部署脚本。
3. 创建任务并添加步骤，为连接、产物命名，在后续步骤引用它们。
4. 检查工作目录，保存并执行，再通过输出、SSH 和文件窗检查结果。

前端发布可以使用：**本地脚本 → 连接服务器 → 上传文件夹 → 远程命令 → 健康检查**。批处理中的 `%CD%` 是当前工作目录，`%~dp0` 是脚本文件所在目录，两者含义不同。

## 语言与外观

支持**英语、简体中文、繁体中文、日语、韩语和西班牙语**。首次启动默认英语，之后使用保存的选择，切换界面语言无需重启。用户内容和外部命令输出保留原文。

内置简约白、深邃黑、书页黄、护眼绿及自定义颜色。面板尺寸、每个任务的流程缩放、参数／文本字号均可记录。

## 本地数据与使用说明

数据放在源码项目或程序 EXE 旁的 `conf/` 中，所需目录自动创建，因此程序目录需要可写。

```text
conf/
├── tasks/          # 以 .txt 保存的 version 2 JSON 流程
├── host/           # 服务器配置
├── scripts/        # 本地和远程脚本
├── .drafts/        # 编辑自动暂存
├── .history/       # 历史版本
├── .logs/          # 按日期保存的任务和 SSH 日志
├── .cache/         # 应用临时缓存
├── downloads/      # 默认下载位置
├── known_hosts     # 已记录的 SSH 主机密钥
└── settings.json   # 语言、主题、布局和偏好
```

- 当前使用 **version 2 JSON**，不再支持旧的 `STEP_xxx=...` 工作流文件。
- 在软件外改名，不会自动同步任务引用。
- 服务器默认路径和命令用于交互式连接；远程流程步骤需要单独设置工作目录。
- 上传备份是可选项，后续脚本或健康检查失败不会自动回滚整个发布。
- 密码保护使用 Windows 用户绑定加密，迁移到其他电脑或账号时可能需要重新填写凭据。
- `conf/` 已被 Git 忽略，应单独妥善备份；即使开启隐藏IP，日志中仍可能包含真实地址及命令输出。

## 打包与许可证

```powershell
.\build.bat
```

免安装输出：`release/DeployFlow/`。制作安装包需要可用的 Inno Setup 6：

```powershell
.\build_installer.bat
```

安装包输出：`installer-output/`。安装后仍需确保程序的 `conf/` 目录可写。

项目使用 PySide6、Qt WebEngine、xterm.js 和 Fabric／Paramiko。自身代码采用 [MIT License](LICENSE)，依赖遵循各自许可证；内置终端相关许可位于 [app/resources/xterm](app/resources/xterm/)。

需要可单独分享的介绍，请参阅 [DeployFlow 项目介绍](docs/PROJECT_OVERVIEW_CN.md)。
