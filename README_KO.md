# DeployFlow

**시각적 배포 워크플로, SSH 터미널, SFTP 파일 관리를 하나로 모은 Windows 데스크톱 도구.**

[English](README.md) · [简体中文](README_CN.md) · [繁體中文](README_TW.md) · [日本語](README_JA.md) · [한국어](README_KO.md) · [Español](README_ES.md)

## DeployFlow가 해결하는 문제

개인 개발자나 소규모 팀이 몇 개의 프로젝트를 배포하기 위해 전체 자동화 플랫폼을 구축하고 설정·유지보수하는 것은 부담이 될 수 있습니다. 반대로 터미널만 사용하면 같은 명령 입력, 경로 복사, 전송 창 전환을 반복하게 되고 배포 단계를 빠뜨리기 쉽습니다.

DeployFlow는 기존 도구와 스크립트를 재사용 가능한 데스크톱 작업으로 구성합니다. 빌드, 연결, 업로드, 스크립트 실행, 상태 확인을 순서대로 수행하고 내장 터미널과 파일 창에서 결과를 확인합니다.

**개인 개발자, 소규모 개발팀, Linux 서버 배포와 문제 해결을 자주 하는 개발자**에게 적합합니다. Java 서비스 배포, 프런트엔드 리소스 업로드, 일상적인 서버 작업에 사용할 수 있습니다. 중앙 스케줄링, 다중 사용자 승인, 분산 실행은 현재 제공하지 않습니다.

![배포 워크플로와 단계별 매개변수](docs/screenshots/workflow.png)

*예: Maven 빌드 → 연결 → 업로드 → 배포 스크립트 → 상태 확인. 스크린샷은 영어 UI이며 사용자 콘텐츠와 명령 출력은 원문을 유지합니다.*

## 배포 절차를 재사용 가능한 워크플로로

순서가 있는 단계로 작업을 구성합니다. 클릭하여 매개변수를 확인하고, 두 번 클릭하여 편집하며, 드래그하여 순서를 바꿉니다. 단계를 선택한 상태에서 추가하면 그 뒤에 삽입하고, 선택하지 않았다면 끝에 추가합니다. 워크플로와 매개변수 패널은 따로 또는 함께 표시할 수 있습니다.

| 단계 | 기능 |
| --- | --- |
| 서버 연결 | 저장된 설정으로 이름이 있는 SSH 연결을 만듭니다. |
| 브랜치 병합／푸시 | 설정에 따라 Git pull, merge, commit, push를 실행합니다. |
| Maven 빌드 | 프로젝트를 빌드하고 이후 업로드에 사용할 JAR 산출물을 식별합니다. |
| 로컬 명령／스크립트 | 작업 디렉터리, 제한 시간, 스크립트 인수를 지정합니다. |
| 업로드 | 산출물·파일·폴더를 전송하며 대상 폴더 생성과 기존 파일 백업을 선택할 수 있습니다. |
| 원격 명령／스크립트 | 지정한 연결에서 명령이나 Shell 스크립트를 실행합니다. |
| 대기 | 지정한 시간 동안 기다립니다. |
| 상태 확인 | 명령을 반복하여 연속 성공 횟수 또는 제한 시간으로 결과를 판정합니다. |

선택한 단계가 없으면 **Run**은 전체 작업을 실행하고, 선택한 단계가 있으면 원래 순서대로 해당 단계만 실행합니다. 오른쪽 클릭으로 한 단계만 실행하거나 해당 위치부터 시작할 수도 있습니다. 출력, 진행 상황, 오류를 확인하고 실행을 중지할 수 있습니다.

부분 실행은 건너뛴 의존 단계를 자동으로 실행하지 않습니다. 필요한 연결·빌드 단계도 같은 실행에 포함하세요.

## 터미널 경로를 바로 조작

- **Ctrl＋마우스 올리기**: 포인터 아래에서 인식 가능한 경로에 밑줄이 표시됩니다.
- **Ctrl＋왼쪽 클릭**: 디렉터리는 터미널과 하단 파일 창이 함께 이동하고, 파일은 해당 파일이 있는 디렉터리로 이동합니다.
- **경로 오른쪽 클릭**: 텍스트 선택 후 또는 선택 없이 경로를 직접 클릭하면 식별 후 해당 작업 메뉴가 표시됩니다.
- **파일 작업**: 텍스트 편집, 인수를 입력하여 스크립트 실행, 권한 변경, 로그 실시간 추적, 마지막 N줄 보기, 키워드 검색을 제공합니다.

현재 서버에서 확인할 수 있는 경로여야 합니다. 상대 이름에는 디렉터리 정보가 필요하며 SSH 탭마다 별도의 디렉터리 문맥을 유지합니다.

![터미널과 연동되는 파일 창](docs/screenshots/remote-files.png)

## 서버 설정과 자주 쓰는 위치

주소, 포트, 계정, 인증을 폼에서 관리합니다. 비밀번호와 개인 키 정보를 모두 보관할 수 있고 선택한 인증 방식을 사용합니다. 서버마다 여러 디렉터리와 선택적 명령을 저장하여 기본 위치를 설정하거나 특정 위치로 바로 연결할 수 있습니다.

![서버 연결 설정](docs/screenshots/server-config.png)

비밀번호 보호와 **Hide IP**를 제공합니다. 지원되는 주소 표시 영역에서 `192.168.10.25`를 `192.**.**.25`로 표시하며 연결에는 원래 값을 사용합니다. 주소를 편집하려면 숨기기를 끄세요. 저장된 로그나 임의의 원격 출력까지 익명화하지는 않습니다.

## SSH 작업 공간과 서버 모니터링

탭 옆 **+**로 다른 저장된 서버를 엽니다. 편집 화면 아래의 터미널 또는 넓은 **Terminal mode**를 사용할 수 있습니다. Qt WebEngine과 xterm.js를 사용하며 Shell 자동 완성, 명령 기록, 복사·붙여넣기, 중단, 재연결을 지원합니다.

측면에는 Linux OS·커널, 가동 시간, 부하, CPU, 메모리, 스왑, 디스크, 실행 중인 프로그램의 포트·사용량·명령 정보를 표시합니다.

![SSH와 서버 상태](docs/screenshots/ssh-monitor.png)

프로세스를 중지하거나 재시작을 시도하는 메뉴가 있습니다. 재시작은 **권장하지 않음**으로 표시됩니다. 원래 시작 스크립트, 파이프, 로그 리디렉션을 완전히 복원할 수 없으므로 필요한 경우 원래 스크립트나 서비스 관리자를 사용하세요.

## 두 가지 파일 관리 화면

**2열 SFTP 창**은 왼쪽에 로컬 드라이브와 폴더, 오른쪽에 서버를 표시합니다. 선택한 항목을 업로드하거나 로컬 목록 및 Windows 탐색기에서 원격 목록으로 파일·폴더를 드래그할 수 있습니다.

![로컬 및 원격 파일 전송](docs/screenshots/sftp-transfer.png)

**내장 원격 파일 패널**은 터미널 아래에서 폴더 트리, 경로 탐색, 방문 기록, 파일 정보를 제공합니다. 옆의 **Logs** 탭에서는 현재 연결의 로그를 봅니다.

업로드·다운로드, 원격 복사·잘라내기·붙여넣기, 이름 변경, 삭제, 새 파일·폴더, 권한 변경, 별도 텍스트 편집기를 지원합니다. 원격 클립보드는 동일한 서버 연결 식별자 안에서 동작합니다. 여러 전송 작업을 관리하며 진행 중인 작업을 삭제하면 취소됩니다. 다운로드 후 저장 위치를 열 수 있으며, 원격 파일을 탐색기 폴더로 드래그하여 그 위치에 다운로드할 수도 있습니다.

## 스크립트, 변경 기록, 로그

저장된 스크립트를 작업에서 참조합니다. 로컬 형식은 `.bat`, `.cmd`, `.ps1`, `.sh`, `.bash`, 원격 워크플로 형식은 `.sh`, `.bash`입니다.

![스크립트 편집기](docs/screenshots/script-editor.png)

작업·설정·스크립트는 초안을 자동 저장하고 **Save／Ctrl＋S**로 정식 파일에 반영합니다. 버전 기록에서 미리 보기, 복원, 다중 선택, 삭제를 할 수 있습니다. 앱 안에서 설정이나 스크립트 이름을 바꾸면 현재 JSON 워크플로, 초안, 워크플로 기록의 참조를 갱신합니다.

실행 및 SSH 로그는 날짜별로 저장됩니다. 파일명에는 생성 시각이, 항목에는 타임스탬프가 포함됩니다. 출력 창을 비워도 로그 화면에서 확인하거나 삭제할 수 있습니다.

![저장된 로그](docs/screenshots/logs.png)

## 시작하기

Windows 64비트용이며 현재 개발 환경은 Python 3.12입니다. 원격 작업에는 SSH／SFTP가 필요하고, 모니터링과 원격 스크립트는 주로 Linux 대상입니다. 사용하는 단계에 따라 Git, JDK, Maven 또는 Maven Wrapper, Node.js／npm, 로컬 Shell용 Bash를 준비하세요.

프로젝트 루트에서 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\start.bat
```

IDE 또는 직접 실행:

```powershell
.\.venv\Scripts\python.exe app\qt_main.pyw
```

포터블 버전은 전체 폴더를 유지하고 `DeployFlow.exe`를 실행합니다. 서버와 스크립트를 저장하고, 작업 단계·연결 이름·산출물 참조·작업 디렉터리를 설정한 뒤 저장하고 실행하세요.

프런트엔드 배포 예: **로컬 스크립트 → 연결 → 폴더 업로드 → 원격 명령 → 상태 확인**. 배치 파일의 `%CD%`는 현재 작업 디렉터리, `%~dp0`는 스크립트 자체의 디렉터리입니다.

## 조작과 화면 설정

| 영역 | 조작 |
| --- | --- |
| 워크플로 | 두 번 클릭하여 편집, 드래그하여 순서 변경, Ctrl＋클릭 다중 선택, 빈 공간 드래그 영역 선택. |
| 캔버스 | 휠 확대·축소, 오른쪽 버튼 드래그 이동. |
| 편집 | Ctrl＋S 저장, 매개변수·텍스트 패널에서 Ctrl＋휠로 글자 크기 변경 및 기억. |
| 원격 파일 | Ctrl＋C／X／V, Delete, F2, Ctrl＋A. |
| 버전 기록 | Ctrl＋클릭, Shift＋클릭, Ctrl＋A. |

영어, 중국어 간체·번체, 일본어, 한국어, 스페인어를 지원합니다. 처음에는 영어이며 이후 저장한 선택을 사용하고 재시작 없이 변경됩니다. 사용자 콘텐츠와 외부 출력은 번역하지 않습니다. 밝은색, 어두운색, 종이색 노랑, 녹색, 사용자 지정 색상을 제공하며 패널 크기, 작업별 확대 비율, 글자 크기를 기억합니다.

## 데이터와 주의 사항

데이터는 소스 또는 EXE 옆의 `conf/`에 저장됩니다. 필요한 폴더는 자동 생성되므로 해당 위치에 쓰기 권한이 필요합니다.

```text
conf/
├── tasks/          # version 2 JSON, 확장자 .txt
├── host/           # 서버 설정
├── scripts/        # 스크립트
├── .drafts/        # 초안
├── .history/       # 버전 기록
├── .logs/          # 날짜별 로그
├── .cache/         # 캐시
├── downloads/      # 기본 다운로드 위치
├── known_hosts     # SSH 호스트 키
└── settings.json   # 언어, 화면, 환경 설정
```

- 이전 `STEP_xxx=...` 형식은 지원하지 않습니다. 앱 밖에서 이름을 바꾸면 참조가 갱신되지 않습니다.
- 서버 기본 위치와 명령은 대화형 연결용입니다. 원격 워크플로의 작업 디렉터리는 따로 설정하세요.
- 업로드 백업은 선택 사항입니다. 이후 단계 실패 시 배포 전체를 자동 롤백하지 않습니다.
- 비밀번호 보호는 Windows 사용자에 연결됩니다. 다른 PC·계정에서는 다시 입력해야 할 수 있습니다.
- `conf/`는 Git에서 제외됩니다. 별도로 안전하게 백업하세요. IP를 숨겨도 로그에 실제 주소가 포함될 수 있습니다.

## 빌드와 라이선스

`build.bat`는 `release/DeployFlow/`에 포터블 버전을 만듭니다. Inno Setup 6 준비 후 `build_installer.bat`를 실행하면 `installer-output/`에 설치 파일을 만듭니다. 설치 후에도 `conf/`에 쓰기 권한이 필요합니다.

PySide6, Qt WebEngine, xterm.js, Fabric／Paramiko를 사용합니다. 프로젝트 자체는 [MIT License](LICENSE), 의존성은 각각의 라이선스를 따릅니다. 터미널 관련 라이선스는 [app/resources/xterm](app/resources/xterm/)에 있습니다. [중국어 프로젝트 소개](docs/PROJECT_OVERVIEW_CN.md)도 제공합니다.
